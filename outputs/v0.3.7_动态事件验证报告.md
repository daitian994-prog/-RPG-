# v0.3.7 动态事件验证报告

验证日期：2026-08-17

## 结论

常规事件不再从20个固定模板中抽取。运行时先由程序根据当前状态生成新的完整事件候选，再由Event Director进行权重结算与Seed抽取。章节终局仍为明确编写的固定事件，不属于常规事件池。

## 40次跨地点模拟

- 即时生成候选事件：480个。
- 不同组件组合：427种。
- 实际抽取：40次，40个不同机械事件ID。
- 不同显示标题：29个；标题相同时，参与者、关键物、压力或线程事实仍可能不同。
- 分类分布：环境17、个人16、世界线程4、英雄3。
- 覆盖事件意图：10种。
- 旧事件ID `e01`—`e20` 抽取次数：0。

## 动态输入

每次候选池Seed至少包含：游戏ID、地点、世界时间、全部线程阶段/紧迫度/认知/结算状态、人物伤势、六项核心能力与玩家关注目标。

每个候选由以下独立组件组成：地点现场、参与者、关键物、现场压力、事件类别、事件意图、当前线程事实或英雄身份，以及三条不同核心能力路线。

## 程序权威

- Dynamic Event Generator负责现场事实、选项、属性、难度和基础结果。
- Event Director负责权重、节奏、重复抑制和最终抽取。
- Check Engine负责概率、Roll和Tier。
- Outcome Engine负责奖励、状态、线索、关系及世界写回。
- AI Narrator只能扩写已经确定的动态事件，不能发明第四个选项或改写规则结果。

## 验收标准

- 相同状态快照生成完全相同的候选池与抽取结果。
- 世界时间、人物能力/伤势或线程状态变化会改变候选组合与ID。
- 每个动态事件均有3条程序生成选项，且至少使用2种不同核心能力。
- 世界线程事件包含当前Stage事实但不会自行推进Stage。
- 英雄交叉由地点、当前目标和低频预算共同限制。
